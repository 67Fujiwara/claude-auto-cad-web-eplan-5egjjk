# 工具貸出管理 Web アプリ（Google Apps Script）

工具に貼った QR コードをスマホで読むと貸出申請画面が開き、「誰がどの工具をいつまで使っているか」を一覧で把握できます。
返却日を過ぎた工具は毎朝メールで催促します。Google スプレッドシート + Google Apps Script（GAS）+ メールだけで動きます。

## ファイル構成

| ファイル | 役割 |
| --- | --- |
| `appsscript.json` | プロジェクト設定（タイムゾーン Asia/Tokyo、Web アプリの公開設定） |
| `Code.gs` | 本体。初期化 `setup()`、画面のルーティング `doGet()`、貸出/返却/延長の処理、催促 `dailyCheck()`、トリガー登録 `installTriggers()` |
| `Notify.gs` | 管理者への通知の入口 `notifyManager(event)`。人（メール）/ AI の切り替えはここだけ |
| `Ai.gs` | AI 管理者 `AiManager`（スタブ）。Claude API を呼んで返答を管理者メールへ転送 |
| `Common.html` | 全画面共通の CSS・上部リンク（一覧 / 管理）・JS ヘルパー |
| `Request.html` | 申請画面 `?tool=TOOL_ID001`。その端末で借りている工具があれば先に一覧を出し、複数選んでまとめて返却できる。無ければ申請フォーム（名前・返却日・コメント） |
| `List.html` | 一覧画面 `?view=list`（複数選択してまとめて借りる機能つき） |
| `Admin.html` | 管理画面 `?view=admin` |
| `Print.html` | QR 一括印刷ページ `?view=print&pin=XXXX` |
| `Result.html` | メールリンク操作（返却・延長）の結果表示、エラー表示 |

### スプレッドシートの構成（`setup()` が自動作成）

| シート | 列 |
| --- | --- |
| 工具 | tool_id, 工具名, 状態(空き/使用中), 使用者名, 使用者メール, 返却日, コメント, 端末ID, 工具箱(box_id) |
| 貸出ログ | 日時, tool_id, 工具名, 使用者名, 使用者メール, 開始日, 返却日, 操作(貸出/返却/延長), 備考, 端末ID |
| 設定 | key, value |
| 工具箱 | box_id, 工具箱名, 管理者名, 管理者メール |

設定シートのキー:

| key | 内容 | 初期値 |
| --- | --- | --- |
| `manager_type` | `human`（人の管理者にメール）または `ai`（AI 管理者） | `human` |
| `manager_email` | 管理者メールアドレス | 空（**必ず設定する**） |
| `app_url` | デプロイ後の Web アプリ URL（QR・メール内リンクに使う） | 空（**必ず設定する**） |
| `admin_pin` | 管理画面の PIN（4〜6 桁の数字） | ランダムな 4 桁 |
| `claude_api_key` | AI 管理者用の Claude API キー（今は空でよい） | 空 |
| `notify_on_request` | 貸出時に管理者へメールを送るか（`on` / `off`）。管理画面のチェックで切替 | `on` |

日付はすべて日本時間で、シートには `2026-09-20` の形式（テキスト）で入ります。

## 準備手順

### 1. スプレッドシートを作る

1. Google ドライブで「新規」→「Google スプレッドシート」を作成し、名前を付ける（例: `工具貸出管理`）。
2. メニュー「ファイル」→「設定」→「全般」タブで **タイムゾーンを「(GMT+09:00) 東京」** にして保存。
   （`setup()` でも自動設定しますが、先に合わせておくと安心です）

### 2. Apps Script エディタを開く

1. スプレッドシートのメニュー「拡張機能」→「Apps Script」。
2. 左上のプロジェクト名（無題のプロジェクト）をクリックして名前を付ける（例: `工具貸出管理`）。

### 3. `appsscript.json` を表示して貼り付ける

1. エディタ左の歯車「プロジェクトの設定」→「**「appsscript.json」マニフェスト ファイルをエディタで表示する**」にチェック。
2. 左の「エディタ」に戻ると `appsscript.json` が出るので、中身をこのリポジトリの `appsscript.json` で**丸ごと置き換え**て保存（Ctrl+S / ⌘S）。

### 4. スクリプトファイルを作って貼り付ける

エディタ左の「ファイル」横の「＋」から追加します。**ファイル名は拡張子なし**で入力します（`.gs` / `.html` は自動で付きます）。

| 追加方法 | 名前 | 貼り付ける内容 |
| --- | --- | --- |
| 既存の `コード.gs` を使う（名前を `Code` に変更） | `Code` | `Code.gs` |
| ＋ → スクリプト | `Notify` | `Notify.gs` |
| ＋ → スクリプト | `Ai` | `Ai.gs` |
| ＋ → HTML | `Common` | `Common.html` |
| ＋ → HTML | `Request` | `Request.html` |
| ＋ → HTML | `List` | `List.html` |
| ＋ → HTML | `Admin` | `Admin.html` |
| ＋ → HTML | `Print` | `Print.html` |
| ＋ → HTML | `Result` | `Result.html` |

各ファイルは既定で入っている内容を消してから貼り付け、保存します。
**HTML のファイル名は大文字小文字も含めて正確に**（`Code.gs` から名前で呼び出しています）。

### 5. `setup()` を実行する（シートの初期化）

1. エディタ上部のドロップダウンで `setup` を選び、「実行」をクリック。
2. 初回は承認画面が出ます。「権限を確認」→ 自分の Google アカウントを選択 →
   「このアプリは Google で確認されていません」と出たら **「詳細」→「（プロジェクト名）に移動（安全ではないページ）」** → 「許可」。
3. 実行ログに `setup 完了。... admin_pin=XXXX` と出れば成功。スプレッドシートに「工具」「貸出ログ」「設定」の 3 シートができています。

### 6. 設定シートを確認する

スプレッドシートの「設定」シートを開き、

- `manager_email` … 管理者（通知を受け取る人）のメールアドレスを入力する（空のままだと管理者通知が送られません）
- `admin_pin` … 表示されている 4 桁を控える（好きな 4〜6 桁に変えてもよい）

`app_url` は次の手順で埋めます。

### 7. Web アプリとしてデプロイする

1. エディタ右上「デプロイ」→「新しいデプロイ」。
2. 左の歯車「種類の選択」→「**ウェブアプリ**」。
3. 設定:
   - 説明: 任意（例: `v1`）
   - 次のユーザーとして実行: **自分**
   - アクセスできるユーザー: **全員**（Google アカウント無しでも開けるようにする。「全員」が無い場合は「匿名ユーザーを含む全員」）
4. 「デプロイ」→ 初回は承認画面が出るので手順 5 と同様に許可。
5. 表示される **ウェブアプリの URL**（`https://script.google.com/macros/s/……/exec`）をコピー。

### 8. `app_url` と `admin_pin` を設定する

どちらかの方法で行います。

- **A. 管理画面から**: ブラウザで `（ウェブアプリのURL）?view=admin` を開き、PIN（手順 6 の `admin_pin`）を入力 →「設定」の「Web アプリ URL（app_url）」欄に手順 7 の URL を貼って「保存」。PIN も同じ画面で変更できます。
- **B. スプレッドシートから**: 「設定」シートの `app_url` の value 欄に URL を貼る。

`app_url` は QR コードとメール内リンクの元になるので、**末尾が `/exec` の URL** を正確に入れてください。

### 9. 催促トリガーを登録する（毎朝 8 時）

**簡単な方法**: エディタで `installTriggers` を選んで「実行」。毎日 8〜9 時（日本時間）に `dailyCheck` が動くトリガーが登録されます。

**手動で登録する場合**: エディタ左の時計アイコン「トリガー」→ 右下「トリガーを追加」→

- 実行する関数: `dailyCheck`
- イベントのソース: 時間主導型
- 時間ベースのトリガーのタイプ: 日付ベースのタイマー
- 時刻: 午前 8 時〜9 時
- 保存

（GAS の時間主導トリガーは「8 時台のどこか」で動きます。分単位の指定はできません）

### 10. 管理画面から工具を登録する

`（ウェブアプリのURL）?view=admin` を開き、PIN を入力 →「工具の追加」に工具名を入れて「追加」。
`tool_id` は `TOOL_ID001`, `TOOL_ID002`… と自動採番されます（旧形式の `T001` / `ID001` は `migrateToolIds()` でまとめて変換できます。工具の ID と、スマホごとの「端末ID」は別物です）。各工具のカードに QR 用 URL と QR 画像が出ます。

### 11. QR を印刷して貼る

管理画面の「**QRを一括印刷**」を押すと、全工具の QR と工具名を A4 に敷き詰めた印刷ページが新しいタブで開きます。
上部で **QR サイズ（12〜30mm）** と **工具名の印字の有無** を選べます。「印刷」ボタン（またはブラウザの印刷）で用紙 A4・倍率 100% で印刷し、点線で切り取って工具に貼ってください。

QR サイズの目安（URL が長いため、これより小さいとスマホで読めなくなります）:

| サイズ | 用途 |
| --- | --- |
| 20mm | 標準。ほとんどのスマホで安定して読める |
| 15mm | 小型工具向け。明るい場所で近づけて読む |
| 12mm | 最小。読めるかテスト印刷で確認してから使う |

印刷後は透明テープやラミネートで覆うと、油や擦れに強くなります。
QR 画像は CDN のライブラリ（qrcode.js）で描画します。社内ネットワーク等で読み込めない場合は URL 文字列だけ表示されるので、別の QR 作成ツールにその URL を貼ってください。

## 使い方（利用者）

| 操作 | 方法 |
| --- | --- |
| 借りる | 工具の QR をスマホで読む → 名前・返却日・コメント（任意）を入れて「借りる」 |
| まとめて借りる | 一覧画面で空きの工具の「選択」を押す（青い「選択中」になる）→ 画面下の「借りる」→ 名前・返却日・コメントを入れて「確定」 |
| 返す | 借りたスマホで工具の QR を読む → 「借りている工具」一覧が出るので返す工具を選択（読んだ工具は選択済み）→ 画面下の「返却」→ OK。一覧画面の「返却を選択」→「返却」でも同じ。**借りたときと同じスマホでだけ返却できます**。別の端末からは管理者に依頼 |
| 延長する | 一覧画面の「+3日」「+7日」「日付指定」。または催促メールの延長リンク |

一覧の色: 緑「空き」 / 赤「〇〇さん 9/20まで」 / 返却日を過ぎると濃い赤で「〇〇さん 9/10まで（6日超過）」。超過した工具はカード全体が赤枠になり、先頭に並び、画面上部に「返却期限超過 N 件」と誰が何をいつまでに返す予定だったかの一覧が出ます。管理画面・QR 読み取り後の「借りている工具」も同じ表示です。「工具」シートでも超過行は赤背景・太字になります（`setup()` が条件付き書式を設定）。

## テスト手順

デプロイ直後に、次の順で一通り動かして確認してください。

1. **工具追加**: `?view=admin` → PIN → 「テスト用ドリル」を追加。`TOOL_ID001` ができ、QR と URL が出る。
2. **申請**: カードの URL（`…/exec?tool=TOOL_ID001`）をスマホで開く（QR を読んでも同じ）。
   「テスト用ドリル」「空き」が出るので、名前・返却日・コメント（任意）を入れて「借りる」。
   → 「テスト用ドリル を 9/xx まで借りました」と表示。管理者メールに「【工具貸出】…」が届く。
   → 同じ URL をもう一度開くと「〇〇さんが 9/xx まで使用中」で申請不可になっている。
3. **一覧確認**: `?view=list` を開く。赤いバッジで「〇〇さん 9/xxまで」。スプレッドシートの「工具」「貸出ログ」にも反映されている。
4. **延長**: 一覧で「+3日」→ 返却日が 3 日延びる。「日付指定」で任意の日にも変えられる。管理者に「【工具延長】…」メール。
5. **催促の手動実行**: 「工具」シートで `TOOL_ID001` の「返却日」を **昨日以前の日付**（例: `2026-09-01`）に書き換える。
   エディタで `dailyCheck` を選んで「実行」→ 管理者に「【工具返却】テスト用ドリル の返却日を過ぎています」が届く（使用者名入り）。
   本文の「+3日」リンクを押す → 「延長しました」ページが出て、返却日が今日+3 日になる（超過中は今日を基準に延長）。
6. **返却**: 借りたスマホでもう一度 QR を読む → 「借りている工具」に選択済みで出るので画面下の「返却」→ OK（または一覧の「返却を選択」→「返却」、メールの返却リンク）→ 緑「空き」に戻る。管理者に「【工具返却】…が返却されました」メール。
   同じ返却リンクをもう一度押すと「すでに返却済みです」と出る。
7. **管理画面のログ**: `?view=admin` 下部に貸出 → 延長 → 返却 の順でログが出ている。テスト用の工具は「削除」で消せる（使用中は削除不可）。

## 管理者を AI に切り替える（将来）

通知はすべて `Notify.gs` の `notifyManager(event)` を通ります。切り替えは次のどちらかだけです。

- 管理画面「設定」→「管理者」の **ai** ボタン
- 「設定」シートの `manager_type` を `ai` にする

`ai` のときは `Ai.gs` の `AiManager.handle(event, settings)` が呼ばれます。現在はスタブで、

1. 「設定」シートの `claude_api_key` に Claude API キーを入れる（[Anthropic Console](https://console.anthropic.com/) で発行）
2. イベントを Claude（`https://api.anthropic.com/v1/messages`、モデル `claude-opus-5`）に送り、返答を管理者メールへ転送する

という動きです。API キーが空、または API 呼び出しに失敗したときは自動で人向けのメール通知に戻ります。
エディタで `testAiManager` を実行すると、ダミーイベントで AI 経路を試せます。
`Ai.gs` の中で `readTools_()` や `extendTool_()` など `Code.gs` の関数がそのまま使えるので、「AI が延長を自動承認する」などに育てられます。

`event` の形（`Notify.gs` 先頭のコメントにも記載）:

```js
{
  type: 'request' | 'overdue' | 'extend' | 'return',
  tool: { id, name },
  user: { name, email },
  dueDate: 'yyyy-MM-dd',
  startDate, oldDueDate, returnDate, overdueDays, note,
  links: { request, list, return, extend3, extend7 }
}
```

## 運用メモ・注意点

- **コードを直したら「新しいデプロイ」ではなく「デプロイを管理」→ 鉛筆 → バージョン「新バージョン」→ デプロイ**。これで URL を変えずに更新できます（「新しいデプロイ」だと URL が変わり、QR を貼り直しになります）。
- **メール送信数の上限**: 無料の Google アカウントは 1 日 100 通、Google Workspace は 1,500 通です。催促は「超過 1 件につき管理者 1 通」です。
- **催促は管理者宛てのみ**: 申請画面にメール欄が無いため、使用者本人には送れません。管理者メールに使用者名が入るので、管理者が本人に声をかける運用です。「工具」シートの「使用者メール」列に手でアドレスを入れた場合だけ、本人にも返却リンク付きの催促が届きます。
- **催促メールのリンクは押すだけで実行されます**（GET）。メールソフトのリンク先自動チェック機能が動く環境では意図せず延長される可能性があります。気になる場合は一覧画面から操作してください。
- **名前の自動入力**（localStorage）と **管理画面の PIN 保持**（sessionStorage）は、ブラウザのプライバシー設定でサードパーティストレージが遮断されていると効きません（入力し直すだけで動作には問題ありません）。
- **貸出時のメール**: 管理画面の「貸出時に管理者へメールを送る」チェックで切り替えます。オフにしても、返却日超過・延長・返却の通知は届きます。
- **端末ID（なりすまし返却の防止）**: 申請画面を開いたスマホごとにランダムな ID を作ってブラウザに保存し、貸出時に「工具」シートの「端末ID」列へ記録します。一覧画面の「返却」ボタンは、その端末 ID が一致する工具にだけ表示されます。管理画面の「返却（管理者）」と催促メールの返却リンクは端末に関係なく返却できます。ブラウザのプライベートモードや履歴削除で ID が変わった場合も、管理画面から返却してください。
- **工具箱（複数の工具箱・管理者を分ける）**: 管理画面の「工具箱」で工具箱名・管理者名・管理者メールを登録し（`BOX01`, `BOX02`… と採番）、各工具のカードのプルダウンで工具箱を割り当てます。通知メールは **その工具箱の管理者メール** に届き（未設定なら設定シートの `manager_email`）、件名に `[工具箱名]` が付きます。使用者には貸出・返却のたびに「返却時は 山田（1F工具箱）に返却してください」と表示され、一覧画面も工具箱ごとに見出し分けされるので、別の工具箱の工具と混ざりにくくなります。複数の工具箱の工具をまとめて借りた場合は、工具箱ごとに 1 通ずつ通知します。工具箱を使わなくても従来どおり動きます。
- **管理画面の代理操作**: 各工具カードの「借りる（代理）」で使用者名・返却日・コメントを入れて貸し出せます（端末 ID は記録しないので、その人のスマホからでも返却できます）。「返却（管理者）」はどの工具でも返却にできます。
- **コメント欄**: 申請時に任意で入力する 200 字までの自由記入欄です（使用場所など）。一覧・管理画面・管理者メールに表示され、返却すると消えます。内容は貸出ログの「備考」に残ります。
- **スプレッドシートを直接編集する場合**は、返却日を `2026-09-20` の形式で、状態は `空き` / `使用中` で入れてください。tool_id は変更しないでください（QR に埋め込まれています）。
- 同時に 2 人が同じ工具を申請しても、`LockService` により後から押した側は「〇〇さんが使用中です」となり二重貸出は起きません。
- 管理画面・一覧画面は URL を知っていれば誰でも開けます（申請・返却は本人確認をしていません）。管理操作だけ PIN で保護しています。
